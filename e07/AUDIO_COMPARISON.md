# STT/TTS A06 и рабочий E07 — 14.09.2026

**STT менять незачем: веса и native runtime совпадают побайтно. В TTS имеет смысл
исследовать только 4-step sampler: в измерении на одном host он примерно в 1,7 раза
быстрее нашего 8-step. Превосходство в качестве звучания и выигрыш на ГУ не установлены.**

Сравнены фактические assets [релиза A06 v1.0.5](https://github.com/voronoff2803/changan-a06-ru-assistant/releases/tag/v1.0.5),
его SHA `faf79f8cf07e7155eab1ce687ac5725853ec3d2eef293d26adcad448b08bba84`,
исходники A06 `main` на `a6081a57348dd3f8b0bcecdb5d98d834d84a307a` и точный
исходный архив рабочего E07 `afd7b3a5…`. В таблице реализаций ниже A06 означает
этот `main`; его исправления после v1.0.5 не выдаются за уже выпущенный APK.

## Что совпадает

| Компонент | Результат |
|---|---|
| GigaAM-v3 CTC int8 | Одинаковые 224 721 476 байт; SHA `f86ebfa0429ced91be6054fc344827e9c6c2572f3c318416cd974b06f66437ec` |
| ASR tokens, sherpa JNI, ORT Java JNI, штатная ORT | Побайтно одинаковые |
| ASR-конфигурация | mono PCM16 / 16 кГц, 64 mel bins, 3 потока, CPU, greedy CTC |
| Tera encoder/duration/vocoder | Побайтно одинаковые |
| Голос `ru_f2`, unicode indexer, бинарный словарь ударений | Побайтно одинаковые |
| Темп TTS | `durationScale=0.9`, исходный синтез 44,1 кГц, в приложении PCM 24 кГц |

Все фактические размеры и SHA: [measurements/assets.json](measurements/assets.json).
В [GigaAsr](src/com/stand/asr/GigaAsr.java) E07 добавлен собственный буфер сессии
и сериализация `finish(byte[])`. Алгоритм CTC и модель сохранены. Различия качества
распознавания между машинами следует искать во входном аудио и границах фразы:
A06 получает PCM с `wp=1/3`, E07 извлекает PCM из SE и определяет конец локально.
Распознавание одной и той же модели на одной записи повторно за «сравнение двух STT»
не выдаётся; парного живого измерения A06/E07 на одинаковом оборудовании нет.

## Что отличается в TTS

| Участок | A06 `main` | E07 |
|---|---|---|
| Sampler | 4-step, SHA `0407903f36d7dbe09b37e8547d6919ad14d7b5a84ee890ba463645d81302b273` | 8-step, SHA `921a050f19794bf97234ca8ffc0298559eaca466d9f7f3b72ec41dfefb37acc6` |
| Подача предложений | Через штатный `PiperCaTts` streaming callback, commit `72051e9` после v1.0.5 | Через `speakOwned` / AudioTrack с владением, отменой, фокусом и ожиданием полного drain |
| Кеш | 48 реплик в памяти, предварительный прогрев 4 приветствий | 48 предложений в памяти + ограниченный дисковый кеш + 330 заранее синтезированных предложений в APK |
| Согласование женских подтверждений | Исправлено после v1.0.5, commit `c31f3d4` | Уже исправлено тем же способом |
| Ударения | Исправлены пять форм, commit `3b54962`, и «хОда» | Эти исправления уже есть; добавлены слова E07 и версия словаря в ключе кеша |

Основной Java-конвейер `TeraTTS.java` различается только именем sampler. Тексты
шести тестовых фраз после `ttsNormalize` совпали. Ручной лексикон E07 дополнен;
например, в «Все двери закрыты» выбирает «двЕри», A06-лексикон задаёт «дверИ».
Сравнение этой фразы отражает также словарь ударений, а не только sampler.

## Измерение синтеза на host

На одном компьютере, Java/ONNX Runtime 1.17.1, CPU, 2 intra-op потока, один голос,
темп 0.9, seed 1234. По два прогрева движка, затем медиана трёх повторов каждой
фразы с чередованием порядка A06/E07. Кеш, Android playback, обработка микрофона
и сеть не входят в время. Итоговый прогон выполнен после завершения сборки и
smali-проверок. Первичный пробный прогон под параллельной сборочной нагрузкой
в эти числа не включён.

| Фраза | A06 4-step, мс | E07 8-step, мс |
|---|---:|---:|
| Чем могу помочь | 81,9 | 138,2 |
| Заряд батареи: 55 процентов. | 116,8 | 203,9 |
| Запас хода: 247 километров. | 121,8 | 209,4 |
| Установила температуру 22 градуса. | 118,7 | 198,4 |
| Все двери закрыты. | 80,6 | 141,3 |
| Передала команду: закрыть нижний борт и крышу багажника. | 157,0 | 262,6 |

4-step выполняет синтез в **1,67–1,75 раза быстрее**; медиана отношений — **1,70**.
Это не означает такое же ускорение ответа в автомобиле: предзаписанные фразы E07
вообще не проходят neural synthesis при воспроизведении. Проверены ненулевая
энергия и конечность отсчётов; это не оценка разборчивости, тембра или естественности.
Полные измерения и SHA аудиопримеров — [measurements/tts-host.json](measurements/tts-host.json).

Воспроизведение (отдельный компьютер, без установки на ГУ): извлечь `assets/tera/`
из проверенного APK v1.0.5 и подготовить зависимости E07 по [README](README.md), затем:

```sh
python3 e07/tests/compare_tts.py --a06-repo . --a06-assets /path/to/extracted/assets/tera
```

Результат — `e07/out/tts-comparison/index.html` с шестью парами WAV, JSON и журналом.
Для повторения именно этих чисел исходники `stand/` должны соответствовать
зафиксированному `a6081a5`; скрипт фиксирует HEAD сравниваемого репозитория.

## Вывод для E07

Сохраняем работающий захват и STT. Подменять весь TTS-модуль A06 тоже не требуется:
его streaming-идея уже реализована в рабочем пути E07, а внедрение напрямую
затронет другой OEM-интерфейс и жизненный цикл воспроизведения.

4-step sampler — конкретный кандидат для отдельного эксперимента после
прослушивания одинаковых реплик. Для замены понадобятся проверка на ГУ и
инвалидация предзаписанного/дискового PCM-кеша: текущий ключ E07 не содержит SHA
sampler. Простая подмена ONNX при старом кеше смешает результаты разных моделей.
В этой ветке сохранён рабочий 8-step; модели на машине не менялись.
