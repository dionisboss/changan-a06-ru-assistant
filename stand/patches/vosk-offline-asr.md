# Офлайн-русский ASR (Vosk) — стенд + план на машину

## На стенде (работает)
- venv + vosk: `stand/asr/venv`, модель `stand/asr/models/ru-small` (vosk-model-small-ru-0.22, ~87 МБ распак.).
- Распознавание: `asr/venv/bin/python asr/recognize.py <file.wav>` (WAV 16 кГц моно) → русский текст.
- Полный голосовой цикл: `bash asr/voice_to_assistant.sh <file.wav>` →
  Vosk (ru) → broadcast `com.stand.NLU` → CloudNlu → mock/LLM → русский ответ.
- Тест-аудио: `say -v Milena ... -o x.aiff` + `ffmpeg -i x.aiff -ar 16000 -ac 1 x.wav`.
- Проверено: «привет включи музыку и позвони маме» → «Привет! Включаю музыку…»;
  «какая сегодня погода в москве» → корректный русский ответ.

Модели по качеству/размеру: `vosk-model-small-ru-0.22` (~45 МБ, быстрый, командный),
`vosk-model-ru-0.42` (~1.8 ГБ, точнее). Для машины начать с small.

## Онлайн-русский ASR (штатный iFlytek, облако)
Патч `SettingsUtil.getLanguage()→4` уже в car-профиле (`build_sa.sh RUSSIAN_ASR=1`).
Движок iFlytek поддерживает русский в облаке (WSS `/iflytek/v2/autoCar`); работает при сети.
Проверять на реальной машине (на эмуляторе ASR-стека нет).

## Интеграция офлайн-Vosk на МАШИНУ (следующий этап, нетривиально)
Vosk на стенде — это desktop-PoC (валидирует модель+текст-инъекцию). На машине нужен нативный путь:
1. **Vosk arm64 на Android:** `libvosk.so` (arm64-v8a) + модель ru-small в приложение/на раздел
   (или отдельный APK-сервис). Vosk даёт готовые Android AAR/JNI.
2. **Тап аудио с микрофона:** сервис с `AudioRecord` (16 кГц моно) на том же источнике, что ASR,
   ИЛИ хук на аудио-поток в speechassistant (`pcm_recorder`/`RecordController`).
3. **Инъекция текста:** результат Vosk → та же точка, что уже проверена —
   `SpeechTestManager.testCloudNlu(zone, sn, text)` (или напрямую в `CloudNlu`/broadcast `com.stand.NLU`).
4. **Активация:** по тому же жесту пробуждения ассистента (шайба/keycode 231).
Плюсы: полностью офлайн, независимо от iFlytek/Changan. Минус: разработка нативного сервиса + тап аудио.

## Стратегия «офлайн + онлайн»
- Онлайн (сеть есть): getLanguage=4 → облачный iFlytek на русском (точнее, но зависит от сети/облака Changan).
- Офлайн (нет сети / приватность): Vosk ru → текст в тот же пайплайн.
- Арбитраж: пробовать облако, при таймауте/офлайне — Vosk. (Логику выбора добавить в сервис-хук.)

## Чистая инъекция без китайской модели (NO_CN_SR) — 2026-09-01
Разбор `SrBaseSession.m1154` (обработчик `onMSDataProc`, фильтрованный звук):
- `wp`(j=1 старт / 3 конец) приходит от **SE/MS фронт-энда** (wake/gesture + beamforming), НЕ от SR-движка;
- китайский SR кормится `SpeechInterfaceImpl.sendSpeechData(bArr)`; облако — `AiBoxManager.sendAsrRecord`; ещё `saveAsrData`.

Флаг сборки **`NO_CN_SR=1`** (`build_sa.sh`): после нашего `VoskBridge.feed(p0..p6)` вставляет `return-void` →
пропускает подачу в iFlytek-SR, загрузку в облако и сохранение. Итог: **китайское распознавание/NLU/облако не
работают** (экономия CPU + приватность), а wake по жесту/ключевому слову + фильтрованный звук + endpoint (`wp`)
остаются → наш Vosk получает и звук, и границы фразы. Движок SR грузится в память, но не распознаёт (нет входа).
Сборка для авто: `VOSK=1 NO_CN_SR=1 RUSSIAN_ASR=1 PROFILE=car HOST=<mac_ip:port> ./build_sa.sh` (classes7 пересобрать `asr-android/build_dex.sh`).
⚠️ Проверить на авто: приходит ли `wp==3` при starve SR (endpoint от SE). Если нет — добавить Vosk-side finalize по тишине/acceptWaveForm.
